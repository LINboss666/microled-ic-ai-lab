# T1 逐沿时序表（先于 RTL 交付，C 方案）

**任务号** `TCON-T1-20261112` ｜ 时基 100 MHz `CLK_REF`（1 cycle = 10 ns）｜ 方案 **C**（相邻 LATCH→下一 LATCH 定长装载）

本表用于**修正 T0R 两处说法**：
1. 「C 净余量 = 208 周期」→ 208 只是 `976 − 768` 的**朴素差**，忽略了装载要等 `LATCH` 脉冲结束；
   真实毛差 **204**（208 − 4），再扣末数据保护 4，**净余量 = 200 周期（2.00 µs）**。
2. 「s−1 的装载完整落在本槽 [0,767]」→ 错。按 C，装载自前一槽 `LATCH`（828）后 4 周期起，**跨槽**进行，本槽第 624 周期结束。

## 2. 跨槽流水（C 方案的真实起止）

以列 s−1 的装载为例（相对本槽 s 起点，可为负）：

| 段 | 起 | 止 | 说明 |
|---|---|---|---|
| 接收 s | 0 | 767 | 768 B @100 MHz，占满 768 周期 |
| 转发 s−1 | **−144** | **623**（半开区间 **[−144, 624)**） | 自上一槽 `LATCH` 脉冲结束（832）起，长 768 周期 = 7.68 µs；相对本槽起点 = 832−976 = −144，止于 1600−976 = 624（不含） |
| 显示 s−2 | 0 | 767 | 已锁存在 Data 显示 bank |
| `LATCH`(s) | 828 | 831 | 把 s−1 的装载结果原子切换 |

> 修正说明：T0R 写「转发 s−1 = [0,767]」是把**接收窗口**当成了**装载窗口**。
> 按 C，装载自 `LATCH` 起算，因此跨槽；本槽内它只占 `[0,619]`。

## 3. 两套不同截止（回应 R3：不可混用同一数字）

| 截止 | 定义 | 时刻（相对本槽） | 毛余量 | 需扣除 | **净余量** |
|---|---|---|---:|---|---:|
| **`video_receipt_deadline`** | 768 B 必须收齐且 bank 可安全交接 | **828**（`LATCH` 前） | 60（828−768） | 与 bank 仲裁/列标签对比同拍完成，无额外脉宽 | **60 周期（0.60 µs）** |
| **`data_load_deadline`** | 384×2 B 必须发完并满足末数据→下一 `LATCH` ≥40 ns | **1800**（= 下一槽 824） | **204**（= 208 − `LATCH` 脉宽 4） | 末数据保护 4 | **200 周期（2.00 µs）** |

**结论**：两者相差 **140 周期**。T2 的"停顿"用例必须分别引用各自的数字，
**不得**把 200 或 208 周期同时套到 `DE` 停顿上（这是 T0R 的错误）。

## 4. 自洽性检查（脚本化，见 `tcon_cycle_table.py`）

| 约束 | 不等式 | 结果 |
|---|---|---|
| 窗口 + 消隐 = 槽长 | 768 + 208 = 976；768 + 209 = 977 | PASS |
| 装载跨槽不重叠 `LATCH` | 832 + 768 = 1600 ≤ 1800 | PASS（净 200） |
| `LATCH` 脉宽 | 4 周期 = 40 ns ≥ 40 ns | PASS |
| `PWM_START` 脉宽 | 4 周期 = 40 ns ≥ 40 ns | PASS |
| `COL_ID` 建立 | 880 − 864 = 16 周期 = 160 ns ≥ 10 ns | PASS |
| `COL_ID` 保持 | `SCAN_STB` 脉宽 40 ns ≥ 5 ns | PASS |
| 一帧总周期 | 576×977 + 448×976 = 1,000,000 | PASS |
| 接收与转发不同 bank | 接收 [0,767] 与转发 [−148,619] 同时活，`LATCH`(828) 时两者皆已结束 | PASS |
