## 1. 五颗芯片的实际引脚（来自源码，非规格转述）

| 芯片 | 实例数 | 端口（源码实际名） | 时钟/复位 |
|---|---|---|---|
| TCON `tcon_top` | 1 | 输入 `clk_ref, pclk, vsync, col_sync, video_d[7:0], de, cfg_valid, cfg_mode[1:0], run_en, rx_ready, fault_n`；输出 `d0[7:0], d1[7:0], dclk, latch, pwm_start, pwm_tick, blank, col_id[9:0], scan_stb`（另有 status/frame_wrap/slot_start/bank_valid/bytes_* 等观测口） | `clk_ref` 100 MHz，`reset_n` |
| Data `data_driver` | 2 | `reset_n, dclk, din[7:0], din_valid, latch, blank, fault_n, pwm_start, pwm_tick, cfg_hybrid, cfg_lut_we/addr/data/commit` → `ch_en[383:0], ch_pam[1151:0], tick_cnt, col_valid, bytes_rcvd, lut_valid, lut_bank, lut_cmt_bad, err_flags` | `dclk` 50 MHz（TCON 产生） |
| Scan `scan_driver` | 2 | `reset_n, blank, fault_n, scan_stb, col_id[9:0]` → `col_a[511:0]`（+ 诊断 `sel_valid/sel_col/sel_chan/err_stb_outside_blank`） | **无参考时钟**，`posedge scan_stb` |

连线（T5 必须照此接，且不得改 RTL）：

```
TCON.d0  → Data#0.din        TCON.d1  → Data#1.din
TCON.dclk/latch/blank/pwm_start/pwm_tick → 两颗 Data（同一组）
TCON.col_id / scan_stb / blank → 两颗 Scan（同一组）
Data#0.ch_en[383:0] ↔ 偶数行 0,2,…,766    Data#1.ch_en[383:0] ↔ 奇数行 1,3,…,767
Scan#0.col_a[i] → 全局偶数列 2i          Scan#1.col_a[i] → 全局奇数列 2i+1
```

## 2. 两级流水时间线（一句话版）

```
槽 s      ：rx  = s        （D0/D1 各 384 字节在 [832,1600) 跨槽装载）
槽 s+1    ：fwd = s        （LATCH 上升沿 828 原子提交到显示 bank）
槽 s+2    ：disp/lit = s   （blank=0 的 0..767 显示窗，PWM 计数 64 tick）
Scan      ：槽 s 末尾 880 上升沿锁存 col_id，槽 s+1 的显示窗点亮 s-1
```

**P0 风险点（最高优先）**：Data 显示的是 `s`（在槽 s+2 显示），Scan 在槽 s 末尾锁存的是 `s` 的列号；
两者必须在**同一显示窗**对应同一条物理列。T2B 用行为模型验过这条，**T5 必须用真实 RTL 再证一次**，
并且**不能**只比较 TCON 自己产生的两个派生计数器（`bytes_sent` vs `in_col`），必须读 Data 的显示 bank 标签
（`col_valid` + 实际 bank 内容）与 Scan 的 `sel_col/sel_chan` 做跨芯片比对。

## 3. T5 验收必须覆盖（任务书点名）

| # | 检查 | 说明 |
|---|---|---|
| 1 | 同一显示时刻 Data#0/#1 内**实际 bank 的列号/帧号**与 Scan 实际选列一致 | 跨芯片，非派生计数器 |
| 2 | 启动第 0、第 1 列不丢失 | 预充 + 首个 LATCH 的边界 |
| 3 | 污染列（383/385 字节）在流水寿命内**不得导通** | Data `col_valid=0`；Scan 仍会选列 → 结果必须是"该列全暗"，不得错位到邻列 |
| 4 | BLANK/FAULT 优先级在五颗芯片同时有效 | 同一步进全关 |
| 5 | 动态 LUT / 故障时**不得错误选通** | 与 T3-H 新门控联动 |
| 6 | 1024 列环绕 | 列 1023 → 0 的帧边界 |

## 4. P0 / OPEN 风险表

| 风险 | 状态 | 处置 |
|---|---|---|
| `T3_LUT_VALID_OUTPUT_GATE` | **已修待审**（T3-H，69/69） | 待独立复审；T5 不得把它当作"已接受" |
| Scan 端 `fault_n` 释放后旧列恢复导通 | `DERIVED_GATE_NOT_LATCH` | 若系统要求故障锁存到合法帧重启，必须在 TCON 安全合同里补，T5 不得自行假设 |
| 污染列与 Scan 选列的隔离语义 | **OPEN** | T5 需明确定义"暗列"而非"错列" |
| Pure 8-bit PWM（255→256 tick 位宽 / 30 ns） | `OPEN` | 不进 T5 主路径 |
| `PAM_CFG=01` 四档 | `OPEN` | 同上 |
| `blank/fault` 异步路径跨芯片时序 | `OPEN_ASYNC_BLANK` | 需 STA/CDC；T5 数字仿真不覆盖 |
| SPI / 寄存器堆 / 中断 | 未实现 | T5 继续用端口注入配置 |
| 模拟 384 路恒流 + 512 路高侧 | 未实现 | T5 不含 |

## 5. 结论

接口层面没有新的未冻结歧义（上表 OPEN 项均为已知、且不阻断数字联仿）；
T5 的可执行前提是：**先取得 T3-H 独立复审通过**，然后另立 T5 任务书与预算。
