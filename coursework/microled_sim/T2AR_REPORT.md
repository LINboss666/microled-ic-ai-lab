## 2. 三个 P0 的修法（都是 RTL 语义问题，不是测试阈值）

### P0-A 截止边界的 `COL_SYNC` 被误判缺失

**根因比复审指出的更靠前一拍**：`tcon_data_tx` 在**周期 831 的下降沿**预取 byte 0 并锁存 `col_valid`。一次提交要一个 posedge，所以**最后一个可用同步是"在周期 830 被采样"**，不是 831；831 的同步要到 posedge 832 才提交，那时 byte 0 已经发出去了。

- `ACCEPT_LAST = LOAD_START − 2 = 830`（`50 MHz`、`LATCH=828`、装载起点 832 **均未改动**）。
- 截止分支改为**同拍提交感知**：`(slot_cycle==ACCEPT_LAST) && !had_sync && !sync_commit`，不再用本拍的旧 `col_ok` 覆盖同拍的合法提交。
- 新增 `had_sync`（本列是否成功提交过）与 `err_flags[5]`（late sync）。831/832 的同步被**拒绝并单独标记**，不会静默接受成零数据，也不会静默丢弃。

### P0-B 提交后再来第 769 字节未撤销有效位

溢出分支现在同时 `ok<=0` 与 `col_ok<=0`（**保留 `had_sync`**，以免截止分支把"已同步过"误报成"缺同步"）。接口合同 §5 的"第 769 字节 → 整列作废"由此真正成立。

### P0-C 故障跨列起点时 `COL_ID` 滞后

采用**"本槽锁定熄屏"**策略，而不是复位时基：故障在列边界那一刻存在时，`slot_bad` 置位并**关掉该槽全部控制脉冲**（`LATCH`/`PWM_START`/`SCAN_STB`/`PWM_TICK`）。`COL_ID` 可以因此停在上一列，但**该槽不发出任何选通**，所以不可能出现"选通与列号不一致"。下一个干净边界自动重新对齐。实测：`stb25=0 lat25=0 colid25=24`。

## 3. 顺带去掉的一个已披露偏离

T2A 把 DCLK 限制在装载窗内翻转。T2AR **恢复连续 50 MHz**：768 拍窗内恒有 384 个上升沿（与相位无关），byte 0 在"首个采样沿之前的那个下降沿"预取（周期 831 或 832）。因此 T1 的连续 DCLK 断言不需要修改——**49 条一条没降**。

## 4. 新增的可观测与检查

- `err_now[5:0]`：单拍脉冲，专门解决"粘滞标志无法逐列归因"（复审 P1-E）。全部错误用例现在按列判定 delta。
- `slot_bad` 进入 `status[7]`。
- TB 侧独立 `CLK_REF` 边沿计数器测槽长（不读 DUT 的 `slot_cycle/slot_len`）。
- setup/hold 用真实时间戳测（最近数据变化沿到采样沿、采样沿到下一次变化），不再只说"高电平没变化"。
- `acc()` 跨帧映射：帧 0 的 1022/1023 与帧 1 的 col 0 单独入槽，验证 1023→0 的 bank 归属。

## 5. 八次运行：六次失败，全是我的测试台缺陷

| # | 失败点 | 我的错 |
|---|---|---|
| 1 | X3 | `col_sync` 驱动早一拍（驱动器值在目标周期的**前一拍**被采样） |
| 2 | X3 | 故障用 posedge 域的 `slot_cycle`，取到上一槽的值，误伤本列边界 |
| 3 | E4 | 粘滞标志导致同一位第二次出现时没有 delta，无法逐列归因 |
| 4 | T8 | 故障只保持了半拍（逐拍条件在下一拍就复位），`safe` 已恢复 |
| 4 | T8 | 期望值用了被毒化槽位的滞后 `COL_ID`（应为零数据） |
| 5 | X17 | 运行尾部太短，帧 1 的 col 0 窗口没关闭 |
| 6 | X17 | `acc()` 分支顺序错：`c<=27` 先命中，帧 1 的 col 0 被映射到 0 号槽位 |

**没有一次是 RTL 功能错误**；每次都是先定位再改，判据一条没降（49 条不变）。
