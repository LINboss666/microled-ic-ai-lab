# COLUMN_POISON_LIFETIME — 被污染列的寿命：从输入到"不可追回的显示许可"

**任务** `TCON-T2B-20261114` 第 A.4 段（只读，**未仿真、未改 RTL**）
**基线** `d17c5de`｜数据取自 run03 原始 VCD（`tcon_t2a_run03.vcd`）与 `t2ar2_d0d1_samples.csv`
**规格依据** V1.3 §9 段 0323（流水）、§20 段 0917-0920（数据错误→当前/后续列全关，恢复合法帧后才重启）、§9 段 0317（"均锁存熄屏"）

本文回答一个问题：**"出事那一槽熄屏了"之后，那一列的数据还会不会在后面的窗口里被点亮？**
答案：会。这正是上轮复审 `PARTIAL_ACCEPT`、以及"跨流水隔离未通过验收"的具体位置。

## 2. 关键缺口：`slot_bad` 在槽 20 的边界就清了

§20 的动作是「**当前/后续列全关**」，恢复条件是「恢复合法帧，清故障后重新启动」。当前实现是"槽内粘滞"：

```
tcon_top.v.txt:172-176
    if (!reset_n)          slot_bad <= 1'b0;
    else if (tb_start)     slot_bad <= !safe;     // ← 槽 20 的拍 0 就重新判定
    else if (!safe)        slot_bad <= 1'b1;
    else if (col_revoke ...) slot_bad <= 1'b1;
```

槽 20 的 `tb_start` 时 `safe=1` → `slot_bad=0`。于是**槽 20 里的一切照常发生**：

| 阶段 | 时刻 | 槽 19 的污染数据发生了什么 | 是否有熄屏保护 |
|---|---|---|---|
| `LATCH` | 槽 20 的 828 | **把"混合载荷"原子切入 Data 显示 bank**（`slot_bad` 已为 0，`LATCH` 正常发出） | ❌ 无 |
| 显示窗口 | 槽 21 的 `[0,768)` | **点亮列 19 的混合数据**（`lit(21)=19`），`pwm_tick` 64 拍正常 | ❌ 无 |
| `SCAN_STB` | 槽 20 的 880 | 按 V1.3 应锁 19（= 槽 20 的 `disp`），当前实现锁 20 | 选通列与显示列**再差 1**（见 `PIPELINE_LABEL_TIMELINE.md`） |

**结论**：污染列的"显示许可"出现在 **+2 槽的 PWM 窗口**，而熄屏保护只覆盖 **0 槽**。
`slot_bad` 的寿命（1 槽）短于流水的寿命（2 槽），中间那一槽完全没有保护——这就是"控制信号当前槽安全已验，跨流水数据安全未验"的确切原因。

## 3. LATCH 被中断时的另一条污染路径（列 11）

列 11 的故障覆盖 828..836，`LATCH` 的 4 拍脉冲被打断 → 槽 11 的 `LATCH` 完全没发（实测 `latch=0`）。这与列 19 不同：

| 项 | 列 19（晚到 769） | 列 11（LATCH 被打断） |
|---|---|---|
| 槽内 `blank` | 768 起本来就高 | 768 起本来就高 |
| `LATCH` | 正常（槽 19 的 828 之前无故障） | **未发出** |
| `SCAN_STB` | 抑制 | 抑制 |
| 显示 bank 内容 | 被替换成"混合载荷" | **保持上一列（槽 10 的 `LATCH` 切入的列 9）** |
| 后果 | +2 槽点亮混合数据 | Data 显示 bank 与 Scan 选中地址**双双停在旧值**，面板把列 9 的内容再显示一槽（错列重影），不是黑 |

也就是说，"抑制 `LATCH` 与 `SCAN_STB`"并不等于"全关"：它把两个保持器同时冻住，结果是**重复上一列**。V1.3 §20 要求的是「当前/后续列全关」，这里应当 `BLANK` 持续到合法帧，而不是靠"不发沿"。

## 4. 三个必须由合同回答的问题

| 编号 | 问题 | 依据 |
|---|---|---|
| P-1 | 污染标签要不要**随流水推 2 槽**（一个 3 深的 "display permission" 移位寄存器，按 bank 存 per-column `poison` 位）？ | §9「各级附带COLID标签」→ 标签能带，污染位也能带 |
| P-2 | 熄屏持续到"下一个合法列边界"还是"下一个合法帧"？ | §20 原文是「恢复合法帧，清故障后重新启动」→ 更接近**帧级**；同槽策略是本实现的收紧，不满足"后续列全关" |
| P-3 | 若坚持槽级熄屏（不整帧黑屏），是否接受"污染列的显示窗口必须 blank 高"这一条更弱的保证？ | 需要你裁定课程演示的可接受代价 |

我方建议：B 段在 Data 行为模型里给每个 bank 加 `poison` 位，由 `revoke`/`slot_bad` 写入，并沿 `LATCH` 一起推进到显示 bank；`blank` 的表达式改为

```
blank = blank_seq || !safe || slot_bad || display_bank_poison
```

这样才可能满足 §20，也才谈得上"跨流水隔离通过"。**本轮不改代码**，因为这条修改必然改变 `blank` 语义与全部 T1/T2A 断言判据，必须先由你裁定 P-2/P-3。
