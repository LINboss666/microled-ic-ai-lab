# PIPELINE_FRAME_TAG_TIMELINE — 绝对帧号+列号时间线（含跨槽 fwd 前后两段）

**任务** `TCON-T2B-20261114` B0.3 ｜ 基线 `e21af5c` ｜ **未运行仿真**
**依据** `T2B_V13_FROZEN_INTERFACE.md`（本目录）、V1.3 §9 段 0313/0323、§14 段 0709

本文修正上一轮 `../t2b/PIPELINE_LABEL_TIMELINE.md` 的一处过度简化：**槽 s 不是整槽只有一个 `fwd` 标签**。转发窗 `[832,1600)` 跨槽，所以槽 s 的早段仍在转发 `s−1`。

---

## 1. 记号

| 记号 | 含义 |
|---|---|
| `f` / `c` | 绝对帧号 / 帧内列号；绝对槽号 `A = 1024f + c` |
| `L(c)` | 该槽长度，976 或 977（由 576/448 分数累加决定） |
| `rx(f,c)` | 槽 `(f,c)` 内接收的列 |
| `fwd(f,c)` | 该槽新建的转发窗口所载的列（窗口 `[832,1600)`） |
| `fwd_tail(f,c)` | 该槽早段仍在转发的**上一槽窗口尾巴** = `(f,c−1)`，止于 `1600−L(f,c−1)`：`L=976→624`、`L=977→623` |
| `disp(f,c)` | `LATCH@828` 之后 Data **显示 bank** 里的列（稳态 = `(f,c−1)`） |
| `lit(f,c)` | 该槽 `[0,768)` 窗口实际发光的列（稳态 = `(f,c−2)`，跨帧时回绕到上一帧尾部） |
| `scan(f,c)` | `SCAN_STB@880` 锁存的列（应 = `disp(f,c)`） |
| 标签 | 四元组 `(frame_id, col, valid, poison)` |

## 2. 启动：预充两槽（首帧 c=0,1,2）

| 槽 `(f,c)` | 接收 | 早段转发 | 晚段转发 | `LATCH@828` 后 `disp` | `[0,768)` 点亮 | `SCAN_STB@880` |
|---|---|---|---|---|---|---|
| `(0,0)` | c0 | 无（无上一窗口） | c0 | **无效**（c0 的转发 1600 才结束）→ 不发 LATCH，`disp_valid=0` | 无（BLANK 保持） | **抑制**（无有效标签） |
| `(0,1)` | c1 | c0（止于 624） | c1 | **c0**（c0 转发已在上槽 1600 完成）→ LATCH、`disp=c0` | 无（本槽窗口开始时 `disp` 还无效，BLANK 保持） | **c0**（第一次有效选通） |
| `(0,2)` | c2 | c1（止于 624/623） | c2 | c1 | **c0** | c1 |
| `(0,3)` | c3 | c2 | c3 | c2 | c1 | c2 |

- 预充 = 槽 0、槽 1 无有效显示；**首列 c0 在槽 2 点亮**，即"接收→显示 2 个列周期"（§9 段 0313）。
- `SCAN_STB` 的第一次有效值出现在槽 1（锁 c0），与"槽 2 点亮 c0"配对 —— 选通比点亮早一槽、晚于 `LATCH`，正是 §14 次序。

## 3. 列 19：预取后第 769 字节，污染必须传到它本来对应的窗口

| 槽 `(0,19)` 拍 | 事件 | 标签 |
|---|---|---|
| `0` | `COL_SYNC`+byte0 | `(0,19)` |
| `0…767` | 768 B 接收完 | `rx=(0,19)` |
| `828` | `LATCH`：切入 c18 | `disp=(0,18)` |
| `[832,1599]` | 转发 c19（384 B） | `fwd=(0,19)`，valid |
| `834` | 第 769 字节（预取之后） | `poison(0,19)=1` |
| `835` | `err_flags[1]`、bank 作废 | — |
| `836` | **`fault_latched`** → `blank=1`；本槽起无 `PWM_START/SCAN_STB/PWM_TICK`，转发被截断 | 显示许可全部收回 |
| `976` 起 | 后续槽 `[0,768)` 的 c18、c19 窗口**全部不点亮**（BLANK 保持），直到 `reset_n` | — |

**关键点**：c19 的显示窗口本应在 `(0,21)` 的 `[0,768)`。按 Q3=B，故障锁存使 `(0,20)`、`(0,21)` 的窗口都没有发光许可，因此污染列**在时序上不可能获得显示**。这比"把 poison 标签搬两槽"更保守，也正是 §20「当前/后续列全关」的字面要求。

同时，Data 行为模型仍会把那一列记为 `corrupt`（它能从自己的 384 B 里解出标签并发现"2 字节真实 + 382 字节零"不自洽），TB 断言该位为 1 —— 这样"污染可检测"是实测事实，而不是文档承诺。

## 4. 帧边界：1022 / 1023 / 下一帧 0

| 槽 `(f,c)` | 接收 | 早段转发 | 晚段转发 | `disp` | `[0,768)` 点亮 | `SCAN_STB` |
|---|---|---|---|---|---|---|
| `(0,1022)` | 1022 | 1021 | 1022 | 1021 | 1020 | 1021 |
| `(0,1023)` | 1023 | 1022 | 1023 | 1022 | 1021 | 1022 |
| `(1,0)` | 0 | **1023**（跨帧尾巴，止于 624/623） | 0 | **1023** | **1022** | **1023** |
| `(1,1)` | 1 | 0 | 1 | 0（`frame_id` 已 +1） | **1023** | **0** |
| `(1,2)` | 2 | 1 | 2 | 1 | **0** | 1 |

- **跨帧尾巴**：槽 `(1,0)` 的早段仍在转发上一帧的 c1023 —— 这就是"只用 10 位列号在跨帧处无法区分"的场景，必须带 `frame_id`。
- bank 归属不受帧边界影响：列 c 恒用 bank `c&1`。c1022(bank0) 的读止于槽 1023 的 624；新帧 c0(bank0) 的写始于槽 `(1,0)` 的 0 → 间隔 352 拍。
- 显示帧边界整体后移 2 列（槽 `(1,0)` 点亮 1022），V1.3 §9 段 0323 明确允许。

## 5. 标签在各级的完整流转（稳态槽 s）

```
输入  ──(f,s)──────────────► RX 写 bank s&1
                                │  [832,1600) 转发
                                ▼
                         fw 标签 (f,s) @ 窗口完成
                                │  LATCH@828（下一槽）
                                ▼
                         disp 标签 (f,s) ，此时 COL_ID=(f,s)
                                │  SCAN_STB@880
                                ▼
                         scan 锁存 (f,s)
                                │  [0,768) 发光
                                ▼
                         点亮 (f,s) —— 绝对槽 s+2
```

TB 的判据只在两处比较，且两条路径**互相独立**：

1. `scan_sel_col`（来自 TCON 的 `COL_ID`，经 Scan 模型锁存）
   vs `dataX.disp_col`（来自 Data 模型**从自己收到的 384 字节里解码**出的标签）。
2. `dataX` 显示 bank 的**行内容**（对照由 `scan_sel_col` 生成的图案）。

任一侧用错计数器都不会同时骗过这两条。

## 6. 本文件的边界

- 全部为静态推导，未仿真；槽内拍号以冻结合同 §1 为准。
- `disp` 无效时（预充、故障、漏 LATCH）不发 `LATCH`/`SCAN_STB` 且 `BLANK` 保持 —— 见 `FAULT_RECOVERY_FSM.md`。
- 不涉及 STA；时序数字均为理想 RTL 相位。
