## 1. 这一轮到底做出了什么（给不写 RTL 的读者）

原来的 TCON 能干一件事：把一列 768 个像素拆成 D0/D1 各 384 个字节送出去。但它有三处和 V1.3 不一致：

1. **同步沿的方向反了**：V1.3 规定 `COL_SYNC` 与第一个字节同拍（列**开始**），旧实现是收满 768 字节后再等一个 `COL_SYNC`（列**结束**）。
2. **扫描选中的列号比数据正在显示的列号大一列**：数据准备的是上一列，扫描地址却给了当前列。
3. **出错只熄当前槽**：被污染的数据在两槽之后仍可能被显示。

本轮把三处一起改掉，并第一次让**两颗 Data 和两颗 Scan 的仿真替身**真正接在 TCON 后面，用"扫描选中的列 == 两颗 Data 实际显示 bank 里的列 == 像素内容"作为核心判据。

| 模块 | 现在做什么 |
|---|---|
| `tcon_video_rx` | `COL_SYNC + DE + byte0` 同拍开列；每列恰好 768 字节；`VSYNC` 必须与首列同沿；缺同步/错位/重复/欠载/溢出/帧错位各自置位并 poison |
| `tcon_top` | 四态 FSM（RESET/IDLE/ACTIVE/FAULT）；追踪"最近一次转发完成的列"与"LATCH 之后的显示 bank 标签"，`COL_ID` 由**实际显示标签**驱动而不是 `s−1` 硬编码；任一错误 → 锁存熄屏直到 `reset_n` |
| `tcon_data_tx` | 输出 `fwd_col/fwd_frame/fwd_poison/fwd_valid` 与 `load_done`，供顶层记录标签；故障时窗关闭、载荷转零 |
| `data_model` ×2 | 按 `LATCH` 边沿自行开窗，收 384 字节；从自己收到的**头两字节解出 (frame, col)**，再用公式校验其余 382 字节；混合/补零列会被判 `cap_bad` |
| `scan_model` ×2 | `COL_ID[0]` 选片、`[9:1]` 选 512 路；仅 BLANK 内 `SCAN_STB` 上升沿才锁存；BLANK 外选通/保持期改选 → 记错 |
| 联合 TB | 预充、正常列、单次错误、锁存、复位恢复、整帧回绕、跨帧标签；39 条断言 |

**为什么这样就不可能"自己骗自己"**：扫描侧拿到的是 TCON 输出的 `COL_ID`；Data 侧拿到的是**它自己从像素数据里解出来的列号**。两边都错成同样的值，需要 TCON 把错误列号写进像素内容本身——而那正是被校验的图案。
