# FAULT_RECOVERY_FSM — 锁存熄屏与恢复（Q3=B）

**任务** `TCON-T2B-20261114` B1.3 ｜ 基线 `e21af5c` ｜ 依据 V1.3 §9 段 0317「均锁存熄屏」、§20 段 0917-0920「当前/后续列全关 … 恢复合法帧，清故障后重新启动」
**裁定** Q3=B：异常后锁存熄屏，直到**明确清除 + 合法帧 + 两级预充**；单个 `VSYNC` 不清故障；本轮以 `reset_n` 作为唯一受支持的清除路径

---

## 1. 四个状态

| 状态 | 进入条件 | 含义 |
|---|---|---|
| `RESET` | `reset_n=0` | 全部输出安全态 |
| `IDLE` | `reset_n` 释放后 | **尚未收到任何视频帧**。只输出时序骨架，不构成任何"显示许可"的声明 |
| `ACTIVE` | 在槽 0 采到 `VSYNC && COL_SYNC`（新帧首列同沿） | 正常：标签、data 转发、显示许可全部生效 |
| `FAULT` | `ACTIVE` 下出现任一锁存事件 | 熄屏锁存；标签冻结；直到 `reset_n` |

```
        reset_n=0            VSYNC&COL_SYNC @槽0
RESET ──────────► IDLE ──────────────────────► ACTIVE
  ▲                 │                            │
  │                 │                            │ 锁存事件
  └─────────────────┴──────── reset_n=0 ◄── FAULT ◄┘
```

**`IDLE` 为什么存在（必须显式声明）**：旧 T1 骨架测试只测时基，不送任何视频。若"未收到同步"就判故障并锁存，T1 的 `R4_ready_blank_low`/`R6_recover_blank_low` 会被判死。因此把"从未见过帧"与"帧内出错"分开：`IDLE` 出骨架（`LATCH/PWM_START/SCAN_STB` 照常，数据为零，`COL_ID = 本地列计数`），一旦见过合法帧首就进 `ACTIVE`，此后一切按 V1.3。这不是给测试让路的开关——`IDLE` 不发出任何"某列已显示"的断言，TB 也不在 `IDLE` 阶段做显示列比较。

## 2. 锁存事件（`ACTIVE` 内，任一命中即 `FAULT`）

| # | 事件 | 判据 | `err_flags` |
|---|---|---|---|
| E1 | 缺列首同步 | 槽 0 拍没有 `COL_SYNC` | `[3]` |
| E2 | 同步错位/晚到 | `COL_SYNC` 出现在槽内非 0 拍 | `[5]` |
| E3 | 重复同步 | 同一槽内第二个 `COL_SYNC` | `[2]` |
| E4 | 欠载 | 起始合法但到 830 拍 `idx<768` | `[0]` |
| E5 | 溢出 | 第 769 字节 | `[1]` |
| E6 | 帧边界错位 | `VSYNC` 不在槽 0（或槽 0 无 `VSYNC` 却在别处出现） | `[4]` |
| E7 | 列序错误 | 输入列号 `in_col` ≠ 本地列号 `tb_col` | `[2]`（与 E3 合一，见冻结合同 §7） |
| E8 | 预取后撤销 | 已提交列在 831 拍后再被第 769 字节作废 | `[1]` |
| E9 | `fault_n` 在 `ACTIVE` 期间拉低 | 电平 | —（`fault_seen` 粘滞） |

`fault_n` 的语义按 §12 段 0496 定为**电平**：`IDLE` 下只门控（与旧行为一致，T1 可回归）；`ACTIVE` 下视为数据完整性事件而锁存（保守、fail-safe）。

## 3. 各状态的输出许可

| 输出 | `RESET` | `IDLE` | `ACTIVE`（健康） | `ACTIVE`（`disp_valid=0`，预充） | `FAULT` |
|---|---|---|---|---|---|
| `BLANK` | 1 | `blank_seq \|\| !safe` | `blank_seq \|\| !safe` | **1** | **1** |
| `LATCH` | 0 | `latch_seq && safe` | `latch_seq && safe && fw_in_valid` | 0 | **0** |
| `SCAN_STB` | 0 | `stb_seq && safe` | `stb_seq && safe && disp_valid` | 0 | **0** |
| `PWM_TICK` | 0 | `tick && window && safe` | `tick && window && safe && disp_valid` | 0 | **0** |
| `D0/D1` | 0 | bank 内容（无有效时为 0） | bank 内容 | 0 | **0** |
| `COL_ID` | 0 | `tb_col`（骨架） | `disp_col`（`LATCH` 更新） | 保持 | **冻结** |
| `status[7]` | 0 | 0 | 0 | 0 | **1** |

`disp_valid` = 最近一次 `LATCH` 切入的 bank 的 `valid && !poison`；预充两槽内为 0，因此两槽的窗口 `BLANK` 保持、无 `LATCH`/`SCAN_STB` —— 这就是"预充不选通"的落地。

## 4. 恢复路径（本轮唯一受支持：`reset_n`）

```
FAULT --reset_n=0--> RESET --reset_n=1--> IDLE --VSYNC&COL_SYNC@槽0--> ACTIVE
                                                                        │
                                        预充槽0/1（disp_valid=0，BLANK 保持）
                                                                        ▼
                                                          槽2 起恢复显示（disp=c0）
```

**为什么单个 `VSYNC` 不清故障**：
1. `VSYNC` 只是边界信号，不证明该帧的 1024 列合法；
2. 故障时 bank 里可能留着"混合载荷"，标签被冻结，仅凭 `VSYNC` 解除会让它在下一帧继续被 `LATCH` 选中；
3. §20 要求「清故障」与「恢复合法帧」是**两个**条件。

**合法帧判据（写下来备用，本轮不作清除输入）**：`VSYNC` 与 `COL_SYNC` 同沿于槽 0；随后 1024 列每列都有合法起始同步且恰好 768 B；整帧无锁存事件；两槽预充完成。
本轮未实现 SPI/寄存器清故障，因此**只用 `reset_n`**，并在报告里声明：这是课程模型的替代路径，不是"自动恢复"。

## 5. TB 必须证明什么（对应任务书 B2.5）

| # | 断言 | 说明 |
|---|---|---|
| F1 | 锁存后 `blank` 保持到 `reset_n` | 不再有"下一个 `tb_start` 就清" |
| F2 | 锁存期间 `LATCH/SCAN_STB/PWM_TICK` 计数为 0 | 显示许可全部收回 |
| F3 | 锁存期间 `D0/D1` 恒为 0 | 混合载荷不再上总线 |
| F4 | 锁存期间的发光窗口没有 `SCAN_STB` | 面板无选通 |
| F5 | 复位后 `IDLE→ACTIVE` 且预充两槽无选通 | 恢复不跳过预充 |
| F6 | 复位恢复后第一列显示的 `disp_col` = 输入 c0，行内容逐字节正确 | 恢复后不错列 |
| F7 | 故障前已进入 `ACTIVE` 的列，其显示在故障后不再出现 | 污染列无残余显示 |

## 6. 明确不覆盖

`fault_n` 毛刺/亚稳态/同步器；CDC；SPI 清故障；STA/PVT/SOA；真实 LED 光学后果。以上均不得据本文宣称。
