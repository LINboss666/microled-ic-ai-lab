**任务** `TCON-T2B-20261114` B0.2 ｜ 基线 `84a1a71`（其父 `2d49108`，`main=23e471c` 不动）
**唯一设计输入** V1.3 原件 `6b61e4ab…afaa`；引文段号见 `../t2b/SOURCE_MANIFEST.md`
**裁定** Q1=A（只做 V1.3 列首同步，不设正式双模式）、Q2=A（Scan 地址取实际显示 bank 标签）、Q3=B（锁存熄屏直到清故障＋合法帧＋两级预充）

## 1. 输入时序（唯一合法形态）

```
PCLK 上升沿:  →  ┌── byte0 ──┬── byte1 ──┬ ... ┬── byte767 ──┬── (空闲/停顿) ──┐
COL_SYNC:     ───┘ (与 byte0 同沿，1 拍脉冲)
DE:           ───┐‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾┐
```

| 项 | 规定 | 依据 |
|---|---|---|
| `COL_SYNC` 语义 | 新列**首字节边界**，与 byte0 **同一 PCLK 上升沿**采样 | §12 段 0411、§9 段 0324 |
| `DE` | 该沿为 1 表示有效字节；每列**恰好** 768 个 | §9 段 0324、§12 段 0406 |
| `VSYNC` | 帧边界，**与新帧第一个 `COL_SYNC` 同沿** | §12 段 0416、§9 段 0324 |
| 停顿 | 允许短暂停顿，整列必须在装载窗（832）前完成 | §9 段 0324 |
| 无 READY | 输入侧无握手 | §9 段 0324 |

**槽内坐标（CLK_REF 100 MHz，1 拍 = 10 ns）**

| 槽内拍 | 事件 | 备注 |
|---|---|---|
| `0` | `COL_SYNC` + `DE` + byte0 | 偏差一拍即判错位 |
| `1 … 767` | byte1 … byte767（可插入停顿） | |
| `≤ 830` | 第 768 字节必须已被采样 | 831 拍的下降沿要预取 byte0 |
| `768` | `BLANK` 上升 | |
| `828 … 831` | `LATCH`（4 拍 = 40 ns） | 只 BLANK 内 |
| `831` 或 `832` 的下降沿 | TX 预取 byte0（`dclk_r` 相位决定） | 与本合同无关，见 §5 |
| `832 … 1599` | `D0/D1` 各 384 字节转发 | **跨槽**，见 §4 |
| `840 … 843` | `PWM_START` | |
| `880 … 883` | `SCAN_STB`，锁存 `COL_ID` | |

**为什么第 768 字节的截止仍是 830**：预取在 831（或 832）的下降沿读 bank，有效性必须在 831 拍已经可见；830 拍采样的字节在 posedge 831 写进 bank 并置有效 → 5 ns 余量。这是**本实现的相位无关保守截止**，不是 V1.3 原文数值。

## 2. 缓存与两条 Data 通道

| 项 | 规定 |
|---|---|
| TCON 缓存 | 2 × 768 B，列 `c` 用 bank `c&1`（只负责接收/转发，不存帧） |
| `D0` | 行 0,2,…,766 共 384 B，`D0[k] = col_byte[2k]` |
| `D1` | 行 1,3,…,767 共 384 B，`D1[k] = col_byte[2k+1]` |
| `DCLK` | 连续 50 MHz；装载窗内恰好 384 个上升沿 |
| 覆盖保护 | 列 `c` 的**读**止于 `1600`（=槽 c+1 的 624/623），列 `c+2` 的**写**始于槽 c+2 的 0 → 最小间隔 352 拍 |

## 4. 转发窗跨槽：一槽里有两个 fwd 标签

以下 `L = len(槽 s) ∈ {976, 977}`：

| 区间（以槽 s 计） | 正在转发 | 说明 |
|---|---|---|
| 槽 s 的 `[0, 1600−L)` | **s−1** | 上一槽窗口 `[832,1600)` 的尾部；`1600−L` = 624（L=976）或 623（L=977） |
| 槽 s 的 `[1600−L, 832)` | 无（空闲） | 上一窗口已结束、本窗口未开始 |
| 槽 s 的 `[832, L)` | **s** | 本槽窗口的前半段，余下部分落到槽 s+1 |

因此 V1.3 §9「槽 s 向 Data 装载 s−1」与"本实现槽 s 后半段转发 s"**并不矛盾**：前者指槽 s 的**早段**（上一个窗口的尾巴，`LATCH@828` 会把它切入显示 bank），后者是该窗口的**开启**。这正是上一轮 `PIPELINE_LABEL_TIMELINE.md` 把整槽标成 `fwd=s` 的过度简化，本轮已按"槽+相位"拆开。

**每个流转对象都带四元标签 `(frame_id, col, valid, poison)`**：只有 10 位列号在跨帧处无法区分"上一帧同号列"，所以必须带 `frame_id`。

## 5. LATCH / SCAN_STB 归属

| 事件 | 拍 | 归属的列标签 |
|---|---|---|
| `LATCH` | 828 | 把**刚转发完成**的那一列切入 Data 显示 bank（稳态 = `s−1`） |
| `SCAN_STB` | 880 | 锁存**同一列**（`disp_col`），即下一发光窗口要显示的列 |
| 发光窗口 | 槽 `k` 的 `[0,768)` | 点亮 `disp_col`（稳态 = `k−2`） |

`COL_ID` 由 TCON **内部追踪的"预计显示 bank 标签"**驱动：在 `LATCH` 拍把"最近一次转发完成的 `(frame,col,valid,poison)`"写入 `disp_*`，`COL_ID = disp_col`。不采用 `tb_col−1` 硬编码——启动预充、漏 LATCH、跨帧、重启时 `disp_*` 可能无效，硬编码会算错。

## 6. 状态机（详见 `FAULT_RECOVERY_FSM.md`）

```
RESET --reset_n--> IDLE --VSYNC@槽0 且 COL_SYNC@同沿--> ACTIVE
ACTIVE --任一列/装载/协议错误--> FAULT_LATCHED --reset_n--> RESET
FAULT_LATCHED: blank=1, 无 LATCH/SCAN_STB/PWM_TICK, 数据零, 标签冻结
IDLE: 只出时序骨架（无视频），不声称显示许可；COL_ID = 本地列计数
```

## 7. `err_flags[5:0]` 语义变更（**必须显式登记**）

V1.3 的 `err_flags` 只有 6 位（T2A 合同冻结），列首同步引入的新语义无法完全无歧义容纳。本轮**不改位宽、不改位置**，按下表重新解释，并把影响写在此处而不是藏在代码里：

| bit | T2A/T2AR2 归档口径 | **本轮（V1.3 模式）口径** | 是否有歧义 |
|---|---|---|---|
| `[0]` | sync 时 <768 B（underrun） | 起始合法但到 830 拍仍不足 768 B | 无 |
| `[1]` | 第 769 字节 | 同左 | 无 |
| `[2]` | 同列第二个 `COL_SYNC` | 同列第二个 `COL_SYNC` **或** 输入列号与 TCON 预期不符（列序错误） | **两义合一**，见下 |
| `[3]` | 到截止仍无 sync | 槽 0 拍缺 `COL_SYNC`（缺列首同步） | 无 |
| `[4]` | `VSYNC` 不在 `COL_ID==0` | `VSYNC` 不在槽 0（帧边界错位） | 无 |
| `[5]` | 同期后到（late） | `COL_SYNC` 出现在槽内非 0 拍（错位/晚到） | 无 |

**影响声明**：`[2]` 现在同时表达"重复同步"和"列序错误"。V1.3 §9 段 0317 把"列序错误"列为独立异常类，但 6 位没有空位；新增第 7 位会破坏已交付的 6 位观测契约。因此按任务书"若无法无歧义容纳则记录影响并停在审查闸"处理：**本轮记录，不扩位**；归档的 T2A/T2AR2 断言不按新口径重跑，也不被声明为仍成立。

## 8. 吞吐与静态时序核对（无 STA）

| 项 | 需求 | 本实现 | 结论 |
|---|---|---|---|
| 视频输入 | 1024 列 × 768 B × 100 Hz = **78.64 MB/s** | PCLK 100 MHz × 8 bit = 100 MB/s | 占用 78.6%，够 |
| 每列接收 | 768 B / 列 | 768 拍 @100 MHz，距 831 截止余 63 拍 | 够 |
| Data 吞吐 | 2 × 384 B / 列 @50 MHz | 384 × 8 × 50 MHz = 19.2 MB/s/口 | 够 |
| 末字节→LATCH | ≥ 40 ns | byte767 在拍 767 写入，`LATCH` 在 828 → **610 ns** | 够（理想 RTL） |
| `COL_ID` 建立/保持 | 10 ns / 5 ns | 828 更新、880 锁存 → 建立 **520 ns**；保持到下一 `LATCH` → **920 拍** | 够（理想 RTL） |
| 故障→`BLANK` | ≤ 50 ns 目标 | 组合门控，**≤ 1 拍 = 10 ns** | 够（无 STA，仅 RTL 相位） |
| 复位低脉宽 | ≥ 1 µs | 新 TB 用 **1 µs**；旧 T1 TB 仅 200 ns | T1 为既有激励偏差，本轮不改其激励，只登记 |
| Data 建立/保持 | 3 ns / 1 ns | 5 ns / 15 ns（时间戳实测） | 够（理想 RTL） |

**结论：新接口在 100 Hz 下满足吞吐，不需要动频率。** 以上均为 RTL 相位结论，`STA = NOT_RUN`。

## 9. 端口变更清单

| 模块 | 变更 |
|---|---|
| `tcon_video_rx` | 语义重写（列首同步）；新增输出：`frame_id[5:0]`、`in_col[9:0]`、`col_start_ok`、`poison_col`、`col_err_now[5:0]` 语义调整 |
| `tcon_top` | 新增内部：`frame_id`、`fw_*`（转发标签）、`disp_*`（显示 bank 标签）、`fault_latched`；`COL_ID` 改由 `disp_col` 驱动；`blank` 增加 `fault_latched` 与"无有效显示标签"项 |
| `tcon_data_tx` | 新增 `load_done` 脉冲与 `fwd_col/fwd_frame` 记录；`fault` 输入强制零载荷 |
| 新增 `data_model` | 仿真替身：装载/显示 bank、`valid/poison`、从像素标签字节解出 `(frame,col)`、行内容可读回。**无任何 TCON 反馈引脚** |
| 新增 `scan_model` | 仿真替身：`COL_ID[0]` 选片、`COL_ID[9:1]` 选 512 路、仅 `BLANK` 内且锁存有效才选通 |
