## 2. 冻结条款（V1.3 原文）

### 2.1 混合映射是 LUT，不是位拼接

> 段0218：「推荐Hybrid使用8-bit输入LUT输出PAM_LEVEL[2:0]和PWM_CODE[5:0]；
> 时间码0→关，1…62→同数tick，63→64 tick满窗口。**最高码必须选最高合格电流档和满窗口，黑码必须全关**。」

所以：**不能**把 8-bit 直接当 `{PAM[2:0], PWM[5:0]}` 用掉 9 位里的 8 位，也不能补一个"第 9 位"。
8-bit 是索引，9-bit 是被查出来的值。段0360 再次强调"PAM码3 bit只表示档位选择，
不承诺一个3-bit精密DAC已完成设计"——即 PAM 是**档位选择**，不是模拟量。

### 2.2 位域与寄存器

> 段0687：`GRAY_MAP_DATA` = `[5:0]PWM [8:6]PAM`，RW，复位值 0
> 段0680：`GRAY_MAP_ADDR` = `[7:0]`，非活动 LUT 银行地址 0…255
> 段0692：`GRAY_MAP_CTRL` = `[0]COMMIT [1]VALID [2]ACTIVE_BANK`，写 bit0 提交完整 256 项银行，**仅 SAFE**
> 段0705：「`LUT_VALID` 只代表 256 项写入、码宽和黑满亮码检查通过。光学单调性必须另行标定。」

即 LUT 是**双银行 + 显式提交**：写的时候只动非活动银行，`COMMIT` 之后整银行原子生效，
且 `COMMIT` 只在 SAFE 时被接受。RTL 必须实现这个互锁，否则一列像素可能一半用旧表一半用新表。

### 2.3 为什么 LUT 必须放在装载路径

> 段0359：「LUT移到装载路径是实现性修正：若等到LATCH后用一个50 MHz端口处理384个像素，
> 需要7.68 μs，超过100 Hz下2.085625 μs留白。预计算使原始和映射数据在LATCH同沿切换；
> 末字节至LATCH至少保留2个DCLK周期供流水排空。**双LUT银行只在SAFE且EN=0时更换**。」

数字核对：384 像素 ÷ 50 MHz = 7.68 µs；100 Hz 下的留白预算是 2.085625 µs。
所以映射必须在**接收时就做**，LATCH 同沿一起切换原始 bank 和映射 bank。

### 2.4 存储预算（段0333–0337）

| 项 | 规格 | 折算 |
|---|---|---|
| 原始缓存 | 384×8 装载 + 384×8 显示 | 768 B |
| 混合映射缓存 | 384×9 装载 + 384×9 显示 | 864 B |
| Gray LUT | 256×9 双银行 | 576 B |
| 每颗合计 | | **2208 B**（768+864+576） |

## 3. 推导出来的那部分：256 项 LUT 内容

### 3.1 V1.3 只给了算法和四个数字

> 段0236：「计数方法：枚举每个PAM档与每个时间码，计算理想电荷Q=I×t，对完全相同Q去重。
> 示例仅取 I_PAMk=(k+1)×15/8 μA（k=0…7）……计算表附256码排序抽样LUT；
> **最小相邻电荷间距仅满量程1/512，最大相对线性曲线偏差约21.78%**。」

### 3.2 工具与复现

`tools/gray_lut_derive.py` 按上句逐字实现：8 档 × 64 时间码 = 512 组合，
`Q = (k+1) × ticks(t)`（整数，单位 = 1 tick × 15/8 µA），去重后排序，
按 `round(j × 267 / 255)`（j = 0…255）等距抽 256 项。

四项特征数字**全部对上**：

```
enumerated combinations          : 512
distinct charge values (dedup)   : 268      V1.3 says 268  -> MATCH
full scale                       : 512 units
selected codes                   : 256
monotone                         : True
min adjacent gap, all 268        : 1  (= 1/512 FS)  V1.3 says 1/512 -> MATCH
min adjacent gap, selected 256   : 1
max |Q - linear| / FS            : 21.7800 %   V1.3 says 21.78 % -> MATCH
black code (video 0)             : Q=0, code = PAM 0 / PWM 0
max code (video 255)             : Q=512, code = PAM 7 / PWM 63
rule: black fully off            : True (PWM code 0)
rule: max = highest tier + full  : True (PAM 7 / PWM 63)

RESULT: DERIVED_REPRODUCES_V13
```

工具在四项数字任一不符时**返回非 0**，所以构建不可能悄悄用上一张错表。

产出文件：
- `t3b/GRAY_LUT_DEFAULT.hex.txt` —— 256 行，每行 9-bit 十六进制（`00`…`1FF`）
- `t3b/GRAY_LUT_DEFAULT.csv` —— code / Q / PAM / PWM / ticks / 电流档，便于逐行核对

### 3.3 这张表是什么、不是什么

- **是**：段0236 那个理想模型下"能选出 256 个单调电荷值"的抽样表，
  用于数字验证（PAM 档位 + PWM 导通拍数是否按表产生）。
- **不是**：光学 256 级灰阶的证明。段0236 自己写了「这张表只证明理想模型可以选到256个单调电荷值，
  不能证明线性、鲁棒或可区分的256级光学灰阶」。段0237 说真实硬件要按 I–V/效率曲线重新选档并标定。
- **表不唯一**（复审裁定采纳）：同一理想电荷可由不同 (PAM,PWM) 组合实现
  （例：Q=2 = PAM0/PWM2 = PAM1/PWM1），四项统计数字只约束"电荷单调"，
  **不唯一确定**这 256 项是哪一组组合。选取哪个代表元属于派生实现选择，
  最终必须由真实器件电流、功耗与光学标定决定。因此本表的正名是
  **「理想模型示例映射表」**，不得称"已恢复 V1.3 的唯一原始标定表"。
- 表里相邻 code 的 PAM 档会跳（例如 code 62 = PAM4/PWM13，code 63 = PAM1/PWM33，
  两者 Q 分别为 65 / 66）——这是"电荷单调、档位不单调"的必然结果，不是错误。
  **RTL 不内置这张表**：V1.3 规定 LUT 由 SPI 写入，所以上电全 0、未提交前不可显示；
  这张表只在 TB 里作为"标定镜像"被加载。

## 4. 仍然 OPEN 的部分（不许自行发明）

| 项 | 为什么 OPEN | 本轮怎么处理 |
|---|---|---|
| `PAM_CFG[1:0] = 01`（4 档对照） | V1.3 只写"01=4档对照"，没给 4 档的档位与码映射 | RTL 接受该写入但置 `cfg_unsup` 状态位，行为保持 8 档；**不实现**、不宣称支持 |
| `GRAY_MODE = 00`（Pure 8-bit PWM） | 纯 PWM 需要 30 ns 时间格与 256 tick（段0218/0186），TCON 现有 `PWM_TICK` 是 120 ns / 64 tick | RTL 里 PWM 计数宽度可配（MAX=255 时按 Pure 语义），但 **TCON 侧 30 ns tick 发生器未实现** → 只能做单元级验证，不能宣称系统可用 |
| 光学单调性 / 有效灰阶数 | 段0705：LUT_VALID 只代表写满与黑满码检查 | 只做数字检查，`OPTICAL_MONOTONICITY = NOT_VERIFIED` |
| I_PAM0…7 的真实档值与修调码 | 段0237/0341：由 5 µm LED 的 I–V、效率曲线和光学标定决定 | 数字侧只输出 3-bit 档位码，`PAM_TRIM = NOT_IMPLEMENTED` |
